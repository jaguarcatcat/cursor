# Парсер выдачи Google Новости (Google News)

Скрипт `parse_google_news.py` собирает реальную поисковую выдачу
**Google Новости** (`https://news.google.com/search`, регион RU, язык ru)
по заданным поисковым запросам и сохраняет структурированные данные по
каждой найденной публикации.

## Почему не «обычный» Google-поиск и не только RSS

- `google.com/search?tbm=nws` при автоматических запросах отдаёт
  JS-челлендж/страницу проверки трафика (антибот-защита), а не реальную
  выдачу — использовать напрямую через `requests`/`curl` нельзя.
- RSS-лента (`news.google.com/rss/search`) не защищена, но не содержит
  реального сниппета и не всегда точно отражает порядок карточек в
  веб-интерфейсе.
- Поэтому скрипт рендерит **настоящую страницу Google Новости** в headless
  Chrome через Playwright (так же, как её увидел бы обычный пользователь в
  браузере с русской локалью и регионом RU), дожидается клиентского
  рендеринга (Google News — SPA) и вытаскивает данные прямо из DOM.
- Реальный URL публикации Google хранит в base64-кодированном виде внутри
  служебного атрибута `jslog` каждой карточки — скрипт декодирует его на
  месте (это не «взлом», а просто чтение того же значения, которое браузер
  использует для перехода по ссылке), без обращения к дополнительным
  внутренним API Google.

## Про сниппеты

Веб-интерфейс Google Новости (в отличие от обычной органической выдачи
`google.com/search`) **не показывает** текстовое описание/сниппет под
заголовком — только заголовок, СМИ и время публикации. Поэтому в колонке
`snippet` скрипт всегда пишет `сниппет Google недоступен` — это не баг и не
лень, а честное отражение того, что видно в реальном интерфейсе Google
News. Самостоятельно придумывать текст сниппета скрипт принципиально не
должен и не делает этого.

## Установка

```bash
pip install -r requirements.txt
# Если в системе ещё нет Chrome/Chromium:
python -m playwright install chromium
```

Скрипт автоматически ищет `google-chrome` / `chromium` в стандартных путях
(`/usr/local/bin/google-chrome`, `/usr/bin/google-chrome`,
`/usr/bin/chromium(-browser)`). Свой путь можно указать через
`--chrome-path`.

## Запуск

```bash
python3 parse_google_news.py \
    --query "лобов вадим университет синергия" \
    --query "лобов вадим синергия" \
    --query "лобов вадим" \
    --depth 20 \
    --output-dir output
```

Если не передать ни одного `--query`, скрипт использует три запроса по
умолчанию (те же самые, что указаны выше — про Вадима Лобова и «Синергию»).

## Параметры

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--query` / `-q` | 3 запроса про Лобова/Синергию | Поисковый запрос (можно указать несколько раз) |
| `--depth` | `20` | Сколько первых результатов брать по каждому запросу |
| `--hl` | `ru` | Язык интерфейса |
| `--gl` | `RU` | Регион (страна) |
| `--ceid` | `RU:ru` | Издание Google News (страна:язык) |
| `--output-dir` | `output` | Куда сохранять CSV/JSON |
| `--chrome-path` | автоопределение | Путь к бинарнику Chrome/Chromium |
| `--headful` | выкл. | Запустить браузер в видимом режиме (для отладки) |

## Результат

В `output/` создаются два файла с одинаковым содержимым:

- `google_news_results_<timestamp>.csv`
- `google_news_results_<timestamp>.json`

Колонки:

- `query` — исходный поисковый запрос;
- `position` — позиция сюжета/карточки в выдаче (1, 2, 3…);
- `sub_position` — если несколько публикаций объединены Google в один
  сюжет (кластер), здесь будет `3a`, `3b` и т.д.;
- `title` — заголовок;
- `source` — СМИ/источник, как его подписывает Google;
- `domain` — домен реальной публикации;
- `published_at_display` / `published_at_iso` — дата публикации (как
  показывает Google и в ISO-формате);
- `snippet` — всегда `сниппет Google недоступен` (см. выше);
- `url` — реальный URL публикации (не редиректная ссылка Google);
- `result_type` — эвристически определённый тип результата (новость,
  интервью, подкаст, видео и т.п.);
- `is_clustered_story` / `cluster_size` — признак объединения Google
  нескольких публикаций в один сюжет;
- `relevance_comment` — автоматическая оценка релевантности заголовка
  исходному запросу (эвристика по ключевым словам — рекомендуется
  дополнительно проверить вручную пограничные случаи);
- `checked_at` — момент времени, когда был выполнен запрос (дата
  проверки);
- `notes` — технические примечания (например, если не удалось декодировать
  реальный URL).

## Ограничения и честные оговорки

- Google периодически меняет вёрстку/CSS-классы своих SPA-страниц — если
  скрипт со временем перестанет находить карточки, сначала проверьте,
  не изменились ли селекторы (`c-wiz.PO9Zff`, `.IFHyqb`, `a.JtKRv`,
  `.vr1PYe`, `time.hvbAAd`, `a.WwrzSb`) простым просмотром DOM в браузере.
- Для узких запросов Google News может отдавать меньше `--depth`
  результатов — это не ошибка скрипта, а реальное ограничение выдачи (в
  интерфейсе браузера пользователь увидел бы ровно столько же).
- Оценка релевантности и тип результата — эвристики по ключевым словам в
  заголовке (без загрузки полного текста статей), приведены как ориентир,
  а не как окончательный вердикт.
